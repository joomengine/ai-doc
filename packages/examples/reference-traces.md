# Trace real package graphs without inventing a starter contract

The [repository inventory](../repositories.md) pins all three inspected sources. This page gives an ordered reading exercise for the smaller Hello World graph and names useful larger variants. Its upstream identities are reference identities: retain them for maintenance of the same items, never allocate them to unrelated new work.

## Field Types and Powers are separate contracts

The five Hello World Fields reference four external definitions in the [core Field Type index at `3be64d59378b5650825b97b44dbd58f2cdb82fcb`](https://github.com/joomengine/joomla-fieldtypes/blob/3be64d59378b5650825b97b44dbd58f2cdb82fcb/index.json):

| Definition | Existing GUID |
| --- | --- |
| Text | `201327fe-3067-4316-a155-3fe2a52e05c0` |
| Subform | `7139f2c8-a70a-46a6-bbe3-4eefe54ca515` |
| URL | `8df6e07e-2b16-43ed-a18d-2059fa44cdf1` |
| Usergrouplist | `e2f31181-fbb3-4c3a-859d-72b6b0cff308` |

Package import must resolve those through the appropriate local/Field Type path. The inspected Package container does not register the separate Field Type handler; separately initialize/verify these required definitions through their own channel. A selected repository can also constrain supported dependency lookup. Verify actual persisted relationships instead of assuming a missing external definition was fetched. A concrete Field with matching `xml` still needs its type definition; a type definition alone does not recreate the Field's per-view role. Follow [Field Type integration](../../field-types/workflows/validate-and-integrate.md).

Hello World contains ten distinct literal Joomla Power tokens and **no Super Power token** at this revision. It is therefore not a Super Power integration example. For a real Super Power boundary, inspect [packages' `niceFancyDate` manual Custom Code](https://github.com/joomengine/packages/blob/4fd6ce1f2a11a478abb291d03a1a3b32ceeda5c9/src/custom_code/niceFancyDate/item.json): its code refers to `Super___993fe913_8e36_4800_a5f7_544aa728ee48___Power`, while the package payload does not describe that class as an ordinary package row. This is an existing upstream example, not a recommendation to wrap Joomla's native date facilities unnecessarily.

The inspected [package dependency resolver](https://github.com/vdm-io/Joomla-Component-Builder/blob/408703a857ad937479b1e28de7f693af178dcc83/libraries/vendor_jcb/VDM.Joomla/src/Componentbuilder/Package/Dependency/Resolver.php) scans its supported Custom Code, template, layout and placeholder conventions; it does not emit ordinary package Power edges for every such token. The compiler's Power loading, namespace/import resolution, related Powers and installed runtime are a separate acceptance boundary. Preserve recognized token spelling; configure the appropriate Power repositories and follow [Super Power integration](../../super-powers/workflows/validate-and-integrate.md). Do not invent a package `src/power/<guid>/item.json` or claim all Powers were loaded because the component's package graph resolved.

## Larger variants to inspect deliberately

| Need | Pinned specimen and reading purpose |
| --- | --- |
| More than one root and target | [packages component index](https://github.com/joomengine/packages/blob/4fd6ce1f2a11a478abb291d03a1a3b32ceeda5c9/index/joomla-component.json): select one Demo or application root and trace only its closure; shared identities are not new copies |
| Routing, layouts and templates in an application | [joomla-packages indexes](https://github.com/joomengine/joomla-packages/tree/a0041f0d408ca65ac43796f89a90c88063fe85a8/index): compare Service Directory J5/J6 roots and their actual child configurations |
| A transported folder | [Demo J5 component-files-folders](https://github.com/joomengine/packages/blob/4fd6ce1f2a11a478abb291d03a1a3b32ceeda5c9/src/joomla_component/children/efde995e-60aa-4b39-b644-44349dfb660d/component-files-folders.json): compare original path, normalized `vendor` descriptor, `.zip` key and compiler destination; do not execute or redistribute vendor content without its own review |
| A custom natural-key validation rule | [packages rule `guid`](https://github.com/joomengine/packages/blob/4fd6ce1f2a11a478abb291d03a1a3b32ceeda5c9/src/validation_rule/guid/item.json): identity is `name`, with raw PHP method source, distinct from built-in Joomla rule availability |

Preserve upstream licensing and attribution when reusing actual code/assets. The fixture's CC0 license does not apply to these references. Apply [maintenance](../workflows/maintain.md) when changing the same item; apply fresh identity and dependency planning when creating a different application.
